# 管理员使用说明

## 1. 本地演示登录

1. 先启动后端，再启动前端。
2. 打开 `http://localhost:5173/admin`。
3. 使用本地初始账号 `admin` 和初始密码 `campus-admin-2026` 登录。
4. 首次登录后进入“账号”页面修改密码。完成前，活动管理功能保持锁定。

本地默认使用内存 H2 数据库。重启后端会清空运行期间的改动，并恢复 12 条模拟活动和初始管理员账号。

## 2. 账号页面

账号页面可以查看：

- 当前登录账号和显示名称
- 管理员角色
- 最近登录时间
- 是否仍需修改初始密码

管理员可以在该页面修改密码或退出登录。新密码长度为 10-72 位，不能与当前密码相同。

## 3. 审核与活动维护

登录且完成首次改密后，可以进入“活动管理”：

- 搜索框支持活动标题、分类、主办方和地点。
- 搜索关键词可以和草稿、待审核、已退回、已发布、已取消、已下架状态组合筛选。
- 待审核活动可以直接发布，也可以点击“退回修改”并填写具体原因。
- 退回原因会显示在活动方工作台，活动方修改后可以再次提交。
- 管理员仍可在异常或紧急情况下人工创建草稿，但日常活动应由活动方自行维护。
- 已发布活动可以下架，下架活动可以恢复为草稿。

## 4. 正式部署初始化

MySQL 模式下，在首次启动前设置环境变量：

```powershell
$env:DB_USERNAME="数据库用户名"
$env:DB_PASSWORD="数据库密码"
$env:ADMIN_INITIAL_USERNAME="管理员账号"
$env:ADMIN_INITIAL_PASSWORD="至少10位的初始密码"
$env:ADMIN_INITIAL_DISPLAY_NAME="管理员显示名称"
```

初始管理员只会在 `admin_users` 表为空时创建。初始密码不会写入数据库明文，后端使用 BCrypt 保存密码哈希。

## 5. 安全边界

- 未登录请求不能访问 `/api/admin/**` 管理数据。
- 修改数据的请求需要有效登录会话和 CSRF 令牌。
- 初始密码未修改时，活动管理接口会返回 428 并保持锁定。
- 学生端 `/api/public/**` 接口继续匿名开放。
- 活动方 `/api/organizer/**` 使用独立角色，只能访问所属组织活动，管理员登录不会自动获得活动方权限。
- 正式环境必须使用自定义强密码，并通过 HTTPS 提供服务。
