# 技术方案

## 架构

第一阶段采用前后端分离的单体架构，优先保证功能完整、代码可维护和部署稳定。

## 技术选型

| 层级 | 方案 | 用途 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | 用户界面与接口调用 |
| 后端 | Java 21 + Spring Boot 3.5 | 活动信息管理、审核和 REST API |
| 数据库 | H2 / MySQL 8 | H2 用于本地演示和自动化测试，MySQL 用于正式交付 |
| 数据库迁移 | Flyway | 版本化建表和初始化演示数据 |
| 接口调试 | Apifox 或 Postman | 接口验证 |
| 版本管理 | Git + GitHub | 代码协作与项目展示 |

## 当前数据模型

- `organizers`：主办方/社团信息
- `categories`：活动分类和排序
- `events`：活动标题、简介、详情、时间、地点、状态、来源和演示标记
- `event_entries`：官方链接、二维码图片地址和入口说明

表结构由 `backend/src/main/resources/db/migration` 中的 Flyway 脚本维护。当前 V1 建表，V2 导入 12 条虚构演示活动。

## 已实现的公开接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/public/health` | 后端健康检查 |
| `GET /api/public/categories` | 查询活动分类 |
| `GET /api/public/events` | 查询活动列表，支持 `keyword`、`category`、`from`、`to` |
| `GET /api/public/events/{id}` | 查询活动详情和官方入口 |

Vue 前端优先调用公开接口，后端不可用时降级到内置模拟数据，方便单独展示 H5。后端默认启用 `local` profile 和 H2；`mysql` profile 通过 `DB_USERNAME`、`DB_PASSWORD`、`DB_URL` 读取交付环境连接信息。

## 已实现的管理接口

| 方法与路径 | 用途 |
| --- | --- |
| `GET /api/admin/events` | 查询全部活动，可按状态筛选 |
| `GET /api/admin/events/{id}` | 查询管理端活动详情 |
| `POST /api/admin/events` | 新增活动草稿 |
| `PUT /api/admin/events/{id}` | 编辑活动资料与官方入口 |
| `PATCH /api/admin/events/{id}/status` | 送审、发布、下架或恢复草稿 |
| `GET /api/admin/categories` | 查询活动分类选项 |
| `GET /api/admin/organizers` | 查询主办方选项 |

管理页面位于 `/admin`，支持活动列表、状态统计与筛选、活动表单和状态操作。发布活动前必须配置至少一个官方链接或二维码入口。当前管理接口还没有登录鉴权，只允许本地演示；公开部署前必须完成管理员登录和权限保护。

## 测试策略

- Spring Boot 上下文测试验证数据库迁移和实体映射。
- MockMvc 集成测试验证公开查询，以及管理员新增、编辑、发布、下架、校验和引用数据接口。
- 前端执行 TypeScript 检查与 Vite 生产构建，并在浏览器中验证搜索、详情、链接、二维码和控制台错误。

## 工程约定

- 所有功能先写清楚需求与验收条件，再开始编码。
- 每完成一个可运行功能就提交一次 Git。
- 不直接使用无法解释的代码；对 AI 生成代码先理解、运行并测试。
- 外部链接和二维码必须标明来源，并定期检查是否失效。
