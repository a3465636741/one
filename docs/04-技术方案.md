# 技术方案

## 架构

第一阶段采用前后端分离的单体架构，优先保证功能完整、代码可维护和部署稳定。

## 技术选型

| 层级 | 方案 | 用途 |
| --- | --- | --- |
| 前端 | Vue 3 + TypeScript + Vite | 用户界面与接口调用 |
| 后端 | Java 17/21 + Spring Boot | 活动信息管理、审核和 REST API |
| 数据库 | MySQL 8 | 活动、主办方、分类和外部入口数据 |
| 接口调试 | Apifox 或 Postman | 接口验证 |
| 版本管理 | Git + GitHub | 代码协作与项目展示 |

## 初步数据模型

- organizer：主办方/社团信息
- activity：活动基础信息、时间、地点、人数上限、状态
- activity_entry：官方报名链接、二维码图片地址和入口说明
- category：活动分类
- activity_audit：活动审核记录

## 工程约定

- 所有功能先写清楚需求与验收条件，再开始编码。
- 每完成一个可运行功能就提交一次 Git。
- 不直接使用无法解释的代码；对 AI 生成代码先理解、运行并测试。
- 外部链接和二维码必须标明来源，并定期检查是否失效。
